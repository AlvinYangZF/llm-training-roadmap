Retrieval became semantic.

You type "symptoms of long covid." BM25 looks for documents containing those words. A dense retriever looks for documents about those words — even if they use completely different vocabulary. This chapter is about the shift from lexical to semantic matching.

Why lexical search breaks the vocabulary mismatch problem

BM25 is a 30-year-old scoring function. It counts how often query terms appear in a document, weighted by rarity. It's fast, interpretable, and — on out-of-distribution queries — shockingly hard to beat. But it has one fundamental flaw: it only matches words you typed.

Ask it for "car insurance" and it won't return pages about "auto coverage." Ask for "how to stop hiccups" and it misses "ending a bout of singultus." This is the vocabulary mismatch problem, and for most real queries it's the single biggest source of missed results.

// the asymmetry
BM25 treats the query and document identically — both are bags of words. A dense retriever treats them asymmetrically: the query is encoded by a question-tower; the document is encoded by a passage-tower. Both project to the same vector space, but they're trained for different roles.

Dense Passage Retrieval (DPR) two BERTs, one space

Facebook AI's DPR (Karpukhin et al., 2020) uses two separate BERT encoders. One maps questions to 768-dimensional vectors. The other maps passages. At search time, you encode the question once, then find the nearest passage vectors by dot product.

// DPR scoring
$$\text{sim}(q, p) = E_Q(q)^{\top} E_P(p)$$
where $E_Q$ is the question encoder and $E_P$ is the passage encoder.

The clever bit is training. Each question comes with one positive passage (contains the answer) and several negatives (don't). DPR uses in-batch negatives: during training, the other batch members' positives act as this question's negatives. Free supervision, at scale.

The dual-encoder vs late-interaction split ColBERT enters the chat

DPR's dual encoder compresses a whole passage into one vector. That's fast — an ANN index over N vectors answers queries in milliseconds — but it loses information. A passage that matches on one critical keyword plus many unrelated ones can get buried because averaging dilutes the signal.

ColBERT (Khattab & Zaharia, 2020) keeps one vector per token on both sides, then computes similarity via a late-interaction MaxSim:

// ColBERT MaxSim
$$\text{sim}(q, d) = \sum_{i \in q} \max_{j \in d} \; E_q^{(i)} \cdot E_d^{(j)}$$
each query token takes the max similarity to any doc token; results summed.

Three families of retrievers know the trade-offs

Sparse (BM25)

Term overlap, tf-idf weighted. Fast, zero training, strong baseline. Misses synonyms.
1992 · still everywhere

Dense (DPR)

One vector per passage. Semantic, cheap index, needs training data. Loses fine-grained detail.
2020 · RAG backbone

Late-interaction (ColBERT)

One vector per token. Best quality, biggest index — ~100× storage of DPR.
2020 · top of leaderboards
