If you can\'t measure it, you can\'t ship it.

RAG has two failure surfaces — retrieval and generation — and one user-facing metric. Decompose them: recall@k for retrieval, faithfulness & answer relevance for generation. The trick is keeping eval cheap enough to run on every PR.

Eval set size that suffices

"It feels better" is not a regression test. The instant your RAG pipeline has more than one knob, you need numbers. The good news: a 200-question eval set with three metrics catches 90% of the regressions you\'d ever ship.

Build the eval set

// recipe
1. Sample 200 real user questions (or synthesize from your corpus with an LLM, then human-spot-check).
2. For each: mark gold passage(s), gold answer, and an answer rubric (3-5 facts that must appear).
3. Stratify: easy / hard / impossible (no answer in corpus). Don\'t skip the impossible bucket — it catches hallucination.
