Inference is two jobs in a trench coat.

Prefill is one huge parallel matmul. Decode is a million tiny memory lookups. They share no bottleneck and punish you for running them together on the same hardware.

You type 100 tokens. The model reads them all at once, fires a single huge matmul across every layer, and produces the first output token — maybe 200 ms in. Then it drops into a different mode: one token at a time, bouncing between HBM and SRAM, bottlenecked on memory bandwidth. Everything downstream in this roadmap — paged attention, flash attention, PD separation — exists because these two phases have nothing in common.

The two phases, side by side

A transformer forward pass looks identical whether you're prefilling a 100-token prompt or decoding the 101st token. But the shape of the inputs changes — and with it, the bottleneck.

TTFT vs TBT the metrics that matter

Because the phases behave differently, you measure them differently:

  • TTFT — Time To First Token. The entire prefill cost. Grows with prompt length.
  • TBT — Time Between Tokens (or ITL, Inter-Token Latency). The per-step decode cost. Grows with KV cache size.

A good UX needs TTFT < 500 ms (for responsiveness) and TBT < 50 ms (for smooth streaming). Optimize one and you often worsen the other — which is why serving systems got so complicated.

The KV cache — the real cost driver

During prefill, the model computes keys and values for every prompt token. Throwing them away would force recomputation at every decode step. So we cache them. The cost of that cache is the shape of every serving decision downstream:

// KV cache memory
$$M_{\text{KV}} = 2 \cdot n_{\text{layers}} \cdot d_{\text{model}} \cdot L \cdot B \cdot b_{\text{param}}$$
2 = one for K, one for V. $L$ = seq len. $B$ = batch. $b$ = bytes (FP16 = 2).

Linear growth kills batching

KV cache grows linearly with both sequence length and batch size. A 70B model processing 16 concurrent 8K-token requests needs ~80 GB just for the cache — before the model weights, before activations. This is the problem PagedAttention (ch. 06) and TurboQuant (ch. 11) were built to solve.
