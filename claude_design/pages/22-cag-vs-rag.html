Skip retrieval. Just preload the corpus.

Cache-Augmented Generation puts the entire knowledge base in the LLM\'s KV cache once. Every subsequent query reads from cache, no retrieval, no vector index. When the corpus fits — CAG wins on latency and accuracy.

Cost · upfront prefill

RAG\'s costs are real: retrieval mistakes, latency budget, ranking complexity. CAG asks: if your knowledge fits in 100 K tokens, why not just stuff it into context once and reuse the KV cache forever? Long-context LLMs make this newly cheap.

The math · when CAG wins

CAG\'s upfront cost is one big prefill (e.g., 100 K tokens). Each query then pays only its own decode tokens, with the corpus sitting in the KV cache. RAG re-pays a small prefill per query (the retrieved context), plus retrieval latency. The crossover depends on QPS and corpus size.

Updates · the catch

RAG\'s index updates incrementally — add a doc, embed, push. CAG must reprefill the entire corpus when the underlying knowledge changes. For static or slowly-changing corpora (product manuals, regulations, code-base snapshots) this is fine. For high-churn data (news, chat history) — RAG wins.

Hybrid · the obvious move

Production teams ship both. CAG holds the stable, evergreen knowledge in cache. RAG fetches the fast-moving long tail. The LLM gets context from both, decides which to trust per question. Latency stays low, freshness stays current, accuracy stays high.
