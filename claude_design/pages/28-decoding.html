The model gives you a distribution. You have to pick.

After every forward pass, the LLM hands back a probability distribution over its 200K-token vocabulary. The decoding strategy decides which token actually gets emitted — and that decision is the difference between a robotic recital, a creative riff, and a hallucination.

After softmax, every possible next token has a probability. Greedy decoding picks the max. Sampling rolls a weighted die. Both are valid — what matters is how you shape that distribution before sampling.

Where decoding lives after softmax, before the user sees anything

Each forward pass of the LLM ends with a logit vector $z \in \mathbb{R}^{|V|}$ — one real number per vocabulary entry. The standard softmax converts logits to probabilities:

// from logits to probabilities
$$p_i \;=\; \frac{\exp(z_i / \tau)}{\sum_j \exp(z_j / \tau)}$$

That $\tau$ is temperature — the single most important knob in the whole stack. Once you have probabilities, the decoder picks one token. That token gets appended to the context, and the loop runs again.

Temperature flatten or sharpen

Temperature divides the logits before softmax. Low temperature ($\tau \to 0$) makes the distribution spike at the top token — the model becomes deterministic. High temperature ($\tau \to \infty$) flattens it toward uniform — the model becomes wildly random.

  • τ = 0 → greedy. Always picks argmax. Boring but reproducible.
  • τ = 0.7 → typical chat. Some variety, mostly coherent.
  • τ = 1.0 → identity. Use the model's raw distribution.
  • τ = 1.5+ → creative writing. Watch out for nonsense.

Top-k and top-p truncate the long tail

Even at $\tau = 0.7$, most of those 200K tokens have non-zero probability. The bottom 99.99% are nonsense — but their combined mass is non-trivial, and you'll occasionally roll one. Two truncation strategies fix this:

  • Top-k. Keep only the $k$ highest-probability tokens. Renormalize. Sample. Simple, but $k$ is fixed across all contexts.
  • Top-p (nucleus). Keep the smallest set of tokens whose cumulative probability exceeds $p$. Adapts: confident contexts get few candidates, ambiguous ones get many. Holtzman et al. (2019).

Beam search keep your options open

The greedy/sampling approaches commit to one token per step. Beam search keeps the top-$B$ partial sequences alive in parallel, scoring each by joint probability. At every step, it expands all $B$ beams, scores all candidates, and re-prunes to the top $B$.

// orange = surviving beams · gray dashed = pruned · green = final winner. B = 3.

Beam is great for translation and constrained generation, where there's a "right" answer. It's bad for open-ended chat — it produces flat, repetitive text because high-probability sequences cluster.

// the 2018 finding that changed everything
Holtzman's "The Curious Case of Neural Text Degeneration" showed that beam search and pure greedy both produce repetitive, degenerate text on open-ended generation. Sampling with truncation (top-p) was the fix. Most of today's chat APIs default to top-p.

Production checklist

  • Code / math / extraction: τ = 0 (greedy). Reproducibility > creativity.
  • Chat / Q&A: τ = 0.7, top-p = 0.9. The boring default, and it's right.
  • Creative writing: τ = 1.0–1.3, top-p = 0.95, presence_penalty > 0 to dampen repetition.
  • Structured output (JSON, tools): τ = 0 + grammar/regex constrained decoding.
  • Translation: beam search with B = 4–8 still beats sampling.
