GPT-2 — the decoder-only that scaled.

OpenAI took the right half of the original Transformer, stacked it 48 layers deep, trained it on 40 GB of text, and accidentally shipped the blueprint every major LLM still uses today. Four parameter counts, one recipe.

Context

The 2017 Transformer paper proposed an encoder–decoder architecture for translation. Two years later OpenAI threw out the encoder, flipped causal masking on, and asked: what if we just predict the next token, very well, at scale? The answer became GPT-2 — and the recipe underneath every LLM that followed.

Decoder only half the Transformer, infinitely scalable

The original Transformer had two stacks: an encoder that reads the input sentence, and a decoder that emits the translation, attending to the encoder's output. For language modeling you don't need both — you just need to predict the next token given everything so far. So GPT keeps only the decoder, with two changes:

  • Causal masking. Token $i$ can only attend to tokens $1, \dots, i$. Implemented by setting future positions to $-\infty$ before softmax.
  • No encoder cross-attention. Each block is just self-attention + FFN.

Four sizes, one recipe the scaling experiment

GPT-2 shipped in four sizes. Only three numbers change between them — depth, width, and heads. Everything else (vocab, optimizer, training data, tokenizer) is identical.

Note that d_head = 64 across all sizes. Every Transformer you will meet — Llama, Mistral, Claude, DeepSeek — keeps 64 or 128 as the head dimension. It's the lowest value that keeps attention expressive while staying friendly to GPU tensor cores.

BPE tokenization 50,257 subwords beats 50,000 words

GPT-2 uses byte-pair encoding over bytes. Start with 256 bytes as your base vocabulary, then iteratively merge the most frequent adjacent pair until you have 50,257 tokens. This gives three properties at once:

  • Open vocabulary. Any string can be encoded — if all else fails, drop to raw bytes.
  • Subword compositionality. Rare words like unhappiness split into un + happy + ness — the model gets to reuse what it learned about each piece.
  • Fixed budget. Exactly 50,257 embedding rows, regardless of corpus size.

Pre-LN > Post-LN the one change that made scale possible

The original paper placed LayerNorm after each sublayer (post-norm). GPT-2 moved it to before (pre-norm). This looks trivial; it isn't. With post-norm, gradient magnitudes grow with depth — past 24 layers, training becomes unstable without careful warmup. Pre-norm keeps gradients well-behaved and lets you stack to 100+ layers without tricks.

Weight tying one matrix, two jobs

The embedding matrix $E \in \mathbb{R}^{V \times d}$ maps tokens to vectors at the input. The LM head $W_{out} \in \mathbb{R}^{d \times V}$ maps hidden states back to vocabulary logits at the output. GPT-2 sets $W_{out} = E^{\top}$ — one shared matrix.

This saves $V \cdot d$ parameters (~39 M for GPT-2 Small) and gives a mild regularization effect. Every large LM since has done the same.

The lineage what GPT-2 set in stone

Every mainstream decoder-only LLM since 2019 inherits most of GPT-2 and changes only a few things:

  • GPT-3. Same architecture. 96 layers, 12288 d_model, 175 B params. Same recipe, more scale.
  • Llama. RMSNorm instead of LayerNorm. SwiGLU instead of GELU. Rotary position embeddings. Same skeleton.
  • DeepSeek-V3. Multi-head latent attention, MoE FFN. Still pre-norm decoder blocks.

GPT-2's contribution wasn't a new idea — it was the demonstration that the decoder-only Transformer, scaled, just works.
