Not every token needs every other token.

Full attention costs O(N²) — quadratic in sequence length. Sparse Transformers break the matrix into structured patterns that bring the cost down to O(N√N), opening the door to 65K-token contexts before anyone had heard of RoPE.

The attention matrix is $N \times N$. Double the context, quadruple the cost. For $N = 8192$ that's a 67-million-entry matrix per head per layer. Sparse attention asks: do we really need all of it?

The quadratic wall why long context is expensive

For sequence length $N$ and head dimension $d$, each attention head computes $QK^{\top}$ — shape $N \times N$ — costing $O(N^2 d)$ FLOPs and $O(N^2)$ memory. The memory is the killer: at $N = 32768$, a single head's attention matrix is over 1 GB in FP16.

The key insight attention is already sparse

In a trained Transformer, most attention weights are near zero. Each token only actually pays attention to a handful of neighbors and a handful of globally important tokens. Sparse attention encodes this structurally — we pick which (i, j) pairs to compute in advance.

Child et al. (2019) proposed two patterns that, when composed, give every token a path to every other token in at most two hops:

Dense (full)

O(N²)
Baseline. Every query attends to every key.

Strided

O(N√N)
Local window + every k-th token. Reaches distant positions via "stripes".

Fixed

O(N√N)
Local windows + a handful of global summary tokens at fixed positions.

BigBird

O(N)
Local + global + random. Theoretically sound, approximates full attention.

Connectivity every token reaches every other in 2 hops

The beauty of the strided pattern is that any two tokens are at most two attention hops apart. Token 0 attends to token 5 (local), token 5 attends to token 12 (strided), so token 0's information reaches token 12 in two layers. Stack $L$ layers deep and every token sees everything — just indirectly.

// composition guarantees full receptive field
$$\text{RF}(2) \supseteq \{(i,j) : |i-j| \leq w\} \cup \{(i,j) : (i-j) \bmod s = 0\}$$

Implementation the block-sparse CUDA kernel

Naive sparse attention is slower than dense on GPU — GPUs hate irregular memory access. The trick is block-sparse: pick patterns where non-zero cells form contiguous $b \times b$ blocks (typically $b = 64$). A BSR (block-sparse-row) kernel processes each block as a small dense matmul, recovering tensor-core throughput.

// implementation note
OpenAI's original Sparse Transformer required hand-written CUDA. Modern libraries — FlashAttention, xFormers, triton — generalize this. Most long-context models today (Claude, Gemini) use some form of block-sparse or sliding-window attention internally.

What got built with this the long-context lineage

  • Sparse Transformer (2019). Images, audio, text to 65K tokens. The original.
  • Longformer (2020). Local + global attention for documents.
  • BigBird (2020). Local + global + random; proves approximation guarantees.
  • Mistral / Llama-3 SWA. Sliding-window attention — only local, compose via layers.
  • Gemini 1.5 / Claude. Proprietary long-context designs that combine block-sparse with recall layers.

Sparsity is now the default for contexts beyond 32K. Full attention survives only at short context or in research settings.
