Why decoding is fast: it remembers instead of recomputes.

Without a KV cache, generating token N requires recomputing all N previous K/V projections — quadratic and stupid. With the cache, decode is O(N) compute and O(1) memory writes per step. Every modern serving stack is built around this object.

The KV cache is the single most consequential data structure in modern inference. Every paged-attention scheme, every quantization trick, every batching decision exists to manage it. Understand its shape and the rest of the serving stack falls into place.

Why caching works K and V depend on past tokens, not future ones

At each decode step, the new query attends to all previous keys and values. The clever observation: those keys and values were already computed when their token was processed — and they will never change. So you store them once and reuse forever.

$$K_t = X_{1:t} W_K \quad V_t = X_{1:t} W_V \quad \text{Attn}_t = \text{softmax}(q_t K_t^\top / \sqrt{d}) V_t$$
// $K_{t-1}$ is a strict prefix of $K_t$. Append, don't recompute.

The footprint formula worth memorizing

$$\text{cache\_bytes} = 2 \times L \times N \times h \times d_h \times \text{bytes/elem}$$
// 2 = K and V · L = layers · N = seq len · h = heads · d_h = head dim

At 32k context, a single Llama-70B sequence eats more cache than a whole A100 has. Either you shrink the cache (GQA, MQA, quantization, H2O) or you page it (vLLM/PagedAttention). All of Memory & Serving exists to manage this growth.
