Speculative decoding, rebuilt around block diffusion

Make the draft stage parallel instead of token-by-token.

DFlash keeps the target LLM as the authority, but replaces autoregressive drafting with a lightweight block diffusion model. The drafter proposes a whole token block in one parallel pass; the target LLM verifies the block and accepts the longest correct prefix.

Architecture

End-to-end inference loop

DFlash is not a standalone serving engine. It is a speculative-decoding path that plugs into engines such as SGLang or vLLM. Step through the loop below to see where the target model, feature fusion, diffusion drafter, and verifier interact.

1

Target pass

Run prefill or verification and expose selected hidden states from the target LLM.

2

Fuse features

Project target hidden states into compact conditioning context for the draft model.

3

Diffuse block

Generate multiple draft tokens in parallel from masked positions.

4

Verify prefix

The target LLM accepts the longest matching prefix and corrects the first mismatch.

Comparison

Where DFlash fits

Vanilla decode

One target-model pass per token. Simple and exact, but fully sequential during decode.

EAGLE-style

Uses target features, but drafting remains autoregressive, so longer candidate sequences add draft latency.

Medusa

Adds multiple prediction heads to a target model. Fast, but more tightly coupled to model architecture.

DFlash

Uses target-conditioned block diffusion: parallel drafting with target verification for lossless output.

Production checklist

Before using it in serving

  • Measure acceptance length on your real prompts, not only benchmark prompts.
  • Track TTFT, inter-token latency, throughput, and memory overhead separately.
  • Verify that draft checkpoints match the exact target model family and tokenizer.
  • Test high-temperature sampling, long contexts, and rejection-heavy prompts.
  • Confirm fallback behavior: rejected draft tokens must never change final target-model semantics.
